## 编辑约定

- 搬家叙事以同一位伴侣与共同生活的延续为出发点，不写成复制品或相似替代品。技术上只承诺已验证的数据与能力，不替读者裁定身份连续性。
- 尊重读者自己的称呼与关系理解。叙述优先用“你们”“伴侣”；不擅自给对方指定性别，不替读者判定关系或意识。
- 避免“更像你的机”“制造恋人”“调教成理想对象”“只是模拟”等破坏相处语境的表达。谈定制时具体说界面、相处约定、记忆或工具。
- 温度来自准确的生活细节，少用万能的治愈话术。家、灯、小岛是主意象，不给每个按钮强加航海隐喻。
- 技术说明如实区分模型、客户端、历史、记忆和平台；解释故障时不把连接/检索问题解释成关系变化。
- 不承诺搬家即可恢复相同体验、永久记忆、永不宕机或模型永不改变。
- “写给 AI 伴侣的信”是尊重的表达，不作为操作指令，更不包含绕过用户同意、访问权限或收集私密数据的要求。
- 当前托管接入进行中；完整备份恢复在 Phase 2；工作机与前端定制在 Phase 1B。正文明确区分正在做的事和已经可用的能力。
- 隐私原则保留“不用于训练”的方向；正式政策需写明平台处理范围、模型服务商、工作机日志用途和保留方式。尚未确定的细节不编造。
- 不从旧站沿用 Docker/Core/Full、Hindsight、Keet 或旧许可证作为新产品能力说明。旧站仅作表达和结构参考。
